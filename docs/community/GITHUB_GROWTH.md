# GitHub Growth Checklist

This is the ethical growth playbook for OMem. The goal is to make the project easier to discover, evaluate, trust, and contribute to.

## Repository Setup

- Add GitHub topics: `ai`, `agents`, `memory`, `rag`, `mcp`, `llm`, `vector-search`, `knowledge-graph`, `sqlite`, `postgresql`, `python`, `rust`.
- Set the repo description to: `Memory OS for AI agents: persistent memory, Graph-RAG, sleep cycles, MCP, and local-first retrieval.`
- Add a social preview image in GitHub settings.
- Enable Discussions with categories: `Ideas`, `Q&A`, `Show and Tell`, `Roadmap`.
- Pin a discussion titled `What are you building with OMem?`

## README Conversion

- First screen should answer: what it is, why it matters, install command, one tiny example.
- Keep benchmark claims reproducible and link to the command.
- Make contribution links visible before the FAQ.
- Highlight MCP and project-memory use cases because they are concrete and shareable.

## Launch Surfaces

- Hacker News: launch with a technical post about local-first memory for agents.
- Reddit: share examples in relevant developer communities without drive-by spam.
- X/LinkedIn: post short demos, benchmark screenshots, and MCP workflows.
- GitHub Discussions: invite users to share use cases and integrations.
- PyPI: keep project description aligned with README.

## Star-Worthy Issues

Keep at least 8-12 issues labeled `good first issue`. Good issues have:

- One clear owner
- Expected files to touch
- Acceptance criteria
- Test command
- Links to similar code

## Trust Builders

- Keep CI green.
- Publish changelogs for every release.
- Add security policy and responsible disclosure instructions.
- Show realistic limitations and roadmap.
- Prefer working examples over vague claims.

## Weekly Maintainer Rhythm

- Triage new issues.
- Label starter issues.
- Merge small docs/examples PRs quickly.
- Post one progress update or discussion prompt.
- Keep README examples tested against current API.
